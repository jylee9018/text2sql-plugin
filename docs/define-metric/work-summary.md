# 지표 정의 에이전트 고도화 작업 정리

- 브랜치: `improve/define-metric` (기준: `main` `e250ebb`)
- 기간: 2026-11-21 ~ 2026-11-24
- 대상: 지표 정의 기능 `skills/define-metric`과 이 기능이 쓰는 `t2s` 명령

## 결론

- 지표 정의 에이전트로 만든 지표가 **정의 → 미리 계산 → 승인 → 게시 안내**까지 끊기지 않고 이어지게 됨
- 모든 변경을 시험으로 확인함: `main`에서 먼저 측정하고, 변경마다 같은 시험으로 다시 측정
- 최종 측정(시험 16개 × 3회): 정리 전 47/48, 정리 후 46/48 회차가 모든 항목을 통과
  - 정리 후 실패 2건은 모두 채점 쪽 문제였고, 에이전트의 동작은 맞았음
- 플러그인 효과 확인(플러그인을 끈 실행과 비교)
  - 승인 지표끼리의 비율 요청: 플러그인이 없으면 불필요한 새 지표를 3/3번 만듦, 있으면 0번
  - 연락처 컬럼 요청: 플러그인이 없으면 민감 컬럼을 2/3번 넣음, 있으면 0번

## 왜 했나: `main`의 문제

- **만든 지표를 쓸 수 없음**
  - 에이전트는 지표를 로컬 정의 파일에 적지만, `t2s`의 조회·미리 계산은 Graph 서버만 읽음(커밋 `0034cfb` 이후)
  - 방금 만든 지표의 미리 계산: 0/3
  - 로컬에서 승인해도 질문 답변(ask)에 반영되지 않음
- **승인 요청이 지표 정의 기능으로 가지 않음**
  - "~ 지표 승인해 줘"에 스킬 호출 3/12
  - 나머지는 에이전트가 정의 파일을 직접 고쳐 처리해서, 플러그인의 승인 절차를 거치지 않음
- **핵심 규칙이 설명서 문장으로만 있음**
  - "사용자가 고른 것만 승인", "결정 없는 지표 금지", "민감 컬럼 금지" 등
  - 에이전트가 매번 지킨다는 보장이 없음
- **이런 문제를 잡을 시험이 없음**
  - `evals/`에는 스킬 연결 시험 4개뿐이었고, 지표 정의는 "스킬이 호출되는가"만 확인

## 어떻게 했나

- 계획안을 쓰고 작업 5개로 나눔: [improvement-plan.md](improvement-plan.md)
- **시험을 먼저 만들고, 변경마다 같은 시험으로 비교**
  - `main`에서 3회씩 측정하고, 플러그인을 끈 비교 실행도 함께 돌림
  - 시험을 세 가지로 나눔: 고칠 대상(3회 측정), 지킬 대상(작업마다 1회), 보강 후보(플러그인 없이도 통과)
- **전제**: 로컬 정의 파일(정의 저장소)이 원본이고 Graph는 게시본
  - 그래서 지표 정의는 Graph 없이 로컬 파일만으로 진행
  - 시험도 Graph 서버 없이 실행
- 작업마다 따로 커밋해서, 점수 변화가 어느 변경 때문인지 구분

### 작업 3. 정의를 읽는 곳 정리 (`210364c`)

- `t2s context`·`schema`·`values`·`compile`·`sql`에 `--definition <파일>` 추가
  - 옵션이 있으면 로컬 정의 파일을, 없으면 지금처럼 Graph를 읽음
  - 출력에 정의 출처 표시(`source: local` 또는 `graph`)
  - 승인 전 지표는 로컬에서도 `--allow-draft` 없이는 계산하지 않음
- `SKILL.md`
  - 모든 `t2s` 명령에 `--definition <정의 파일>`을 붙임
  - 승인은 "게시 준비 완료"를 뜻하고, Graph에 게시한 뒤에 답변에 쓰인다고 안내
  - 게시 전 값은 "게시 전 정의로 계산한 값"이라고 표시
- 결과: [eval-task3.md](eval-task3.md)
  - 미리 계산 0/3 → **4/4**
  - 다른 시험 점수 유지

### 작업 4. 규칙 검사를 `t2s check`로 이동 (`3677998`, `472b11b`)

- 파일 전체에 적용하는 검사
  - 민감 컬럼: 연락처·이메일·카드번호·계좌번호·주민번호 등. 필드 식 안에서 읽는 경우도 포함
  - 승인 기록 형식: `approval`에 `by`(역할)와 `at`(날짜)이 있어야 함
- git 마지막 커밋과 비교해 **이번에 바뀐 것**에만 적용하는 검사
  - 이번에 승인된 지표·연결에 승인 기록이 없음 → 문제
  - 새 지표에 `decision`이 없음 → 문제
  - 내용이 바뀌었는데 `revision`이 그대로 → 확인 요청
  - 바뀐 것에만 적용하는 이유: 규칙이 생기기 전에 승인된 지표가 많아서, 파일 전체에 적용하면 경고가 넘침
- 출력에 비교 여부 표시(`compared_with: git HEAD` 또는 `null`)
- 정의 파일을 고칠 때마다 훅(`hooks/check_definition.py`)이 이 검사를 실행
- macOS 시험 환경 대응: `/usr/bin/git` 중간 프로그램이 샌드박스에서 실패해서, 진짜 git 위치를 먼저 씀
- `SKILL.md`
  - 승인할 때 승인 기록(역할·날짜, 사람 이름은 적지 않음)을 함께 적음
  - 민감 컬럼은 보유 여부 같은 파생 필드로도 넣지 않고, 필요하면 데이터 담당자에게 요청하도록 안내
- 단위 테스트 12개 추가. 전체 125개 통과
- 결과: [eval-task4.md](eval-task4.md)
  - 시험 점수 유지
  - 일부 승인 시험에서 승인 기록 6/6

## 측정 중 고친 시험 오류

- 시험 설정이 시나리오 폴더 밖의 경로를 가리켜 실행되지 않음(`turns: 0`) → 시나리오 폴더 안의 `setup.sh`가 공통 스크립트를 부르게 바꿈
- 설명 줄의 따옴표 때문에 YAML 형식 오류 → 설명 전체를 작은따옴표로 감쌈
- 정규식이 여러 줄 식과 `CAST(...)` 감싸기를 놓침 → 표기에 상관없이 지연 조건을 찾도록 넓힘
- 공통 스크립트가 정의 파일을 커밋한 뒤에 시나리오별 준비가 정의 파일을 고침 → 커밋을 준비의 마지막 단계로 분리
- 가중치 0인 채점은 시험 도구가 허용하지 않아 시험 2개가 실행되지 않음 → 그 채점을 빼고 다시 측정

## 전제와 한계

- 전제: 로컬 정의 파일이 원본이고 Graph는 게시본
  - Graph에만 있는 지표가 생기는 운영 방식이면, 지표를 찾는 단계에 Graph 확인을 추가해야 함
- 게시는 플러그인 밖의 절차: 승인한 지표가 답변에 쓰이려면 사람이 Graph에 게시해야 함
- LLM 판정 채점에 오판 2건: 긴 답변에서 기준을 충족한 내용을 놓침
- 정규식 채점이 같은 뜻의 다른 표기를 2번 놓침
- 승인 기록 검사가 실제로 위반을 잡는 장면은 시험에 없음: 에이전트가 매번 기록을 적어서, 단위 테스트로만 확인
- 플러그인 없이도 통과하는 시험 3개: 플러그인 효과를 보여 주지 못함
- 설명서 6단계의 `git diff`는 macOS 시험 환경에서 실패함: 에이전트는 바뀐 부분을 직접 인용해서 넘어감
