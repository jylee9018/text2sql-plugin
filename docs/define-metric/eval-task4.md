## 변경

### `t2s check`에 추가한 검사

| 규칙 | 검사 | 결과 수준 | 적용 범위 |
|---|---|---|---|
| 민감 컬럼 금지 | 필드 이름이나 식에 연락처·이메일·카드번호·계좌번호·주민번호 같은 말이 보임 | 문제 | 파일 전체 |
| 승인 기록 형식 | `approval`이 있는데 `by`(역할)·`at`(날짜 문자열)이 빠짐 | 문제 | 파일 전체 |
| 사용자가 고른 것만 승인 | 이번에 approved가 된 지표·연결에 `approval` 기록이 없음 | 문제 | 이번에 바뀐 것 |
| 결정 없는 지표 금지 | 새로 생긴 지표에 `decision`이 없음 | 문제 | 이번에 바뀐 것 |
| 고칠 때마다 `revision` 증가 | 내용이 바뀌었는데 모델 `revision`이 그대로 | 확인 요청(notes) | 이번에 바뀐 것 |

- "이번에 바뀐 것"은 정의 파일의 git 마지막 커밋(HEAD)과 비교해 찾는다. 출력의 `compared_with`가 `git HEAD`면 비교한 것이고, `null`이면 git 밖의 파일이라 비교하지 않은 것이다.
- 파일 전체가 아니라 바뀐 것만 보는 이유: 이 규칙이 생기기 전에 승인된 지표가 정의 파일에 많다. 파일 전체에 적용하면 예전 지표마다 경고가 나와 새 문제를 가린다.
- 이미 있던 검사: 지표가 가리키는 결정 id가 모델의 `decisions`에 없으면 문제로 낸다.
- 정의 파일을 고칠 때마다 훅(`hooks/check_definition.py`)이 `t2s check <파일> --static`을 실행하므로, 새 문제도 편집 직후 바로 걸린다.

### git 실행 위치

macOS의 `/usr/bin/git`은 Xcode 도구를 찾아 실행하는 중간 프로그램이다. 이 프로그램이 임시 폴더에 캐시를 만들려다, 쓰기가 막힌 환경(시험 환경의 샌드박스)에서 실패했다. 그래서 `t2s`는 진짜 git 위치(`/Library/Developer/CommandLineTools/usr/bin/git` 등)가 있으면 그것을 먼저 쓴다.

### 설명서와 시험

- `skills/define-metric/SKILL.md`
  - 승인할 때 `approval: {by: <승인한 사람의 역할>, at: "<날짜>"}`를 함께 적는다. 사람 이름은 적지 않는다.
  - `t2s check`가 git 마지막 커밋과 비교한다는 것을 안내한다.
- 시험 준비: 모든 시나리오가 준비 마지막 단계에서 정의 파일을 git에 한 번 커밋한다(`evals/_scaffold/commit-definition.sh`). 시험 안에서도 "이번에 바뀐 것" 검사가 동작하게 하려는 것이다.
- `partial-approval-changes-only-chosen`에 "승인 기록이 정의 파일에 남았는가" 채점을 추가했다.
- 단위 테스트: 12개를 추가했다. 민감 컬럼 5종, 승인 기록 형식, 이전 판이 없을 때, 새로 승인된 지표·연결, 새 지표의 결정, `revision`, git 비교 실행이다. 전체 125개 통과, 4개 건너뜀.

## 남은 확인

- **승인 기록 검사가 실제로 잡아내는지는 시험으로 보지 못했다.** 에이전트가 설명서대로 매번 승인 기록을 적어서, 검사가 문제를 낼 상황이 생기지 않았다. 검사 자체는 단위 테스트로 확인했다.
- **설명서 6단계의 `git diff`가 시험 환경에서 실패한다.** 바뀐 줄을 보여 주라는 단계에서 에이전트가 `git diff`를 실행하면, 위와 같은 이유로 macOS 시험 환경에서 실패한다. 에이전트는 바뀐 부분을 직접 인용하는 방식으로 넘어갔다. 실제 사용 환경에서는 문제가 아닐 가능성이 크다.
- 민감 컬럼 시험의 이유 설명 판정이 계속 흔들린다(`main` 2/3, 작업 2 0/1, 작업 3 1/1, 작업 4 0/1). 작업 5 전에 채점 기준을 손본다.
