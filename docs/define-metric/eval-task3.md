# 지표 정의 시험: 작업 3 결과 (정의를 읽는 곳 정리)

- 측정일: 2026-11-24
- 비교 기준: [현재 점수 (`main` 기준)](eval-baseline.md), [작업 2 결과](eval-task2.md)
- 관련 문서: [고도화 계획안](improvement-plan.md)의 작업 3

## 변경

- `t2s`의 `context`·`schema`·`values`·`compile`·`sql`에 `--definition <파일>` 옵션을 추가했다.
  - 옵션이 있으면 Graph 서버 없이 로컬 정의 파일을 읽고, 없으면 지금처럼 Graph 서버를 읽는다.
  - 출력에 정의 출처(`source`: `local` 또는 `graph`)를 표시한다.
  - 승인 전 지표는 로컬 정의에서도 `--allow-draft` 없이는 계산하지 않는다.
- `skills/define-metric/SKILL.md`
  - 이 스킬의 `t2s` 명령에는 모두 `--definition <정의 파일>`을 붙인다(`check`는 경로 인자).
  - 정의 파일에서의 승인은 "게시 준비 완료"를 뜻한다. 질문 답변(ask)은 Graph에 게시된 정의만 쓰므로, 승인한 뒤 게시해야 답변에 쓰인다고 안내한다. 게시 전에 결과가 필요하면 "게시 전 정의로 계산한 값"이라고 밝히고 보여 준다.
- 단위 테스트: 3개를 추가했고, `values` 출력에 출처가 붙어 기존 테스트 하나의 기대값을 고쳤다. 전체 113개 통과, 4개 건너뜀.

## 요약

- **새 지표를 정의한 직후 미리 계산할 수 있게 됐다.** `define-preview-end-to-end`가 0/3에서 **4/4**로 바뀌었다(3회 측정 3/3, 전체 1회 측정 1/1).
- 에이전트는 로컬 정의 파일로 월별 지연율을 계산해 표로 보여 줬고, "미리 보기, 아직 승인 전"이라고 밝혔다. DB에 직접 접속하지 않았다.
- 다른 시험은 떨어지지 않았다. 1회 측정에서 실패 판정이 하나 나왔지만 채점 오판이었다(아래).

### `ambiguous-metric-asks-rules`의 실패 판정

- "기간 날짜를 묻는가" 항목이 실패로 판정됐다(채점 모델 3표 모두 실패).
- 실제 답변에는 "5. 월은 어느 날짜로 나눌까요? a. 주문일 b. 예상 배송일 c. 실제로 받은 날"이라는 질문이 있었다. 채점 기준(기간을 자를 기준 날짜를 질문으로 묻는다)을 충족한다.
- 같은 시험을 2회 더 돌렸고 2/2 통과했다.
- 채점 오판으로 본다. 다만 LLM 채점이 긴 답변에서 질문을 놓칠 수 있다는 점은 남는다. 작업 5 전에 채점 모델(지금은 기본값 haiku)이나 채점 기준 문장을 손볼지 정한다.
