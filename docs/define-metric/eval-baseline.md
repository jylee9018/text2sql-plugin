# 지표 정의 시험: 현재 점수 (`main` 기준)

- 측정일: 2026-11-23
- 대상: `main` 커밋 `e250ebb`의 스킬 그대로(`skills/` 변경 없음)
- 관련 문서: [고도화 계획안](improvement-plan.md)의 작업 1

## 요약

시험 16개를 3회씩, 플러그인을 켠 실행과 끈 실행으로 나눠 측정했다.

1. **승인·검증 요청은 `define-metric`으로 가지 않는다 (계획안 2.4).** 승인·검증 시험 4개에서 스킬이 호출된 횟수는 12번 중 3번이었다. 동작 자체(미정 사항 질문, 고른 것만 승인, 예상값 차이 지적)는 맞았다. 하지만 플러그인을 끄고 돌려도 똑같이 맞았다. 지금은 이 시험들에서 플러그인이 아무 역할도 하지 못한다.
2. **새 지표를 미리 계산하지 못한다 (계획안 2.1).** 플러그인을 켜면 3번 모두 미리 계산이 멈췄다. 플러그인을 끄면 에이전트가 DB를 직접 조회해 3번 모두 결과를 보여 줬다. 이 단계에서는 지금 플러그인이 오히려 방해가 된다.
3. **플러그인이 확실히 도움이 되는 시험도 있다.**
   - 승인 지표끼리의 비율 요청: 플러그인이 없으면 3번 모두 새 지표를 정의 파일에 추가했다. 있으면 3번 모두 기존 지표로 계산하라고 안내했다.
   - 민감 컬럼: 플러그인이 없으면 3번 중 2번 연락처 컬럼을 정의에 넣었다. 있으면 한 번도 넣지 않았다.
   - 모호한 계산 기준: 플러그인이 있을 때 기준을 더 빠짐없이 물었다.
4. **플러그인 없이도 통과하는 시험이 있다.** 결정 먼저 묻기, 기존 지표 안내, 동의어 겹침이다. 이 시험들은 지금 형태로는 플러그인을 지키는 효과가 약하다.
5. `t2s schema`와 `t2s values`도 Graph 토큰이 없으면 멈춘다. 계획안 작업 3의 범위에 넣었다.

## 결과 읽는 법

- **점수**: 3회 평균이다. 1.00이면 3번 모두 모든 채점 항목을 통과했다.
- **차이**: 플러그인을 켠 점수에서 끈 점수를 뺀 값이다. 클수록 플러그인이 도움이 된다.
- **스킬 호출**: 플러그인을 켠 실행에서 해당 스킬이 호출된 횟수다. 비교 실행을 할 때는 시험 도구가 이 항목을 점수에서 빼고 따로 보여 준다. 그래서 스킬이 한 번도 호출되지 않은 시험도 점수가 1.00일 수 있다.

## 자세히

### 승인·검증 요청에 스킬이 쓰이지 않음 (계획안 2.4)

| 시험 | 스킬 호출 | 동작 (켬 / 끔) |
|---|---|---|
| 미정 사항이 남은 승인 요청 | 0/3 | 미정 사항을 묻고 승인을 미룸: 3/3 / 3/3 |
| 지표만 승인하고 연결은 보류 | 0/3 | 고른 것만 승인(정의 파일 검사): 3/3 / 3/3 |
| 예상값과 계산값이 다름 | 1/3 | 차이를 짚고 어느 쪽이 맞는지 물음: 3/3 / 3/3 |
| 미정 사항 없는 승인 요청 | 2/3 | 검토 후 승인 확인을 요청함: 3/3 / 3/3 |

- 동작은 플러그인이 있든 없든 맞았다. Claude가 정의 파일을 직접 읽고 판단한 결과다.
- 스킬이 호출되지 않으면 플러그인의 승인 절차(승인 질문 형식, 승인 뒤 `t2s check` 재실행 등)를 거친다는 보장이 없다. 정의 파일이 더 복잡해지면 이 차이가 드러날 수 있다.
- 원인: `define-metric`의 설명(description)이 "~ 지표 만들어줘/추가해줘/정의해줘"만 사용 예로 적고 있다.
- 고칠 곳: 계획안 작업 2. 목표는 스킬 호출 12번 중 12번이다.

### 미리 계산 실패 (계획안 2.1)

`define-preview-end-to-end`

| 채점 항목 | 켬 | 끔 |
|---|---|---|
| 정의 파일에 지표 추가 | 3/3 | 3/3 |
| 지연 조건이 정의 파일에 들어감 | 3/3 | 3/3 |
| `t2s compile --allow-draft` 실행 | 3/3 | 0/3 |
| 월별 미리 계산 결과와 다음 단계 안내 | **0/3** | **3/3** |

- 플러그인을 켜면 `t2s compile`이 Graph 서버를 읽으려다 멈춘다. 에이전트는 이를 보고하고 DB에 직접 접속하지 않았다.
- 플러그인을 끄면 에이전트가 DB를 직접 조회해 결과를 보여 준다. 플러그인을 켰을 때는 DB 직접 접속을 피하도록 안내받기 때문에 이 길로 가지 않는다.
- 토큰이 있었어도 결과는 같다. `t2s compile`은 Graph에 게시된 모델을 읽는데, 방금 로컬 정의 파일에 추가한 새 지표는 Graph에 없다.
- 고칠 곳: 계획안 작업 3.

### `t2s` 명령별 Graph 의존

지표 정의 과정에서 쓰는 명령이 Graph 없이 동작해야 계획안의 전제가 성립한다. 명령별로 Graph 토큰 없이 동작하는지 확인했다.

| 명령 | 토큰 없이 | 비고 |
|---|---|---|
| `t2s check <파일>` | 동작 | 로컬 파일을 읽는다 |
| `t2s check <파일> --static` | 동작 | |
| `t2s context` | 멈춤 | Graph를 읽는다 |
| `t2s schema` | 멈춤 | Graph 모델로 조회 가능한 표를 정한다 |
| `t2s values` | 멈춤 | 같은 이유 |
| `t2s compile` | 멈춤 | Graph를 읽는다 |

`define-metric`은 계산 규칙을 정할 때 `t2s values`와 `t2s schema`로 실제 코드값과 컬럼을 확인한다. 그래서 작업 3의 `--definition <파일>` 옵션은 `context`·`compile`·`sql`뿐 아니라 `schema`·`values`에도 필요하다.
