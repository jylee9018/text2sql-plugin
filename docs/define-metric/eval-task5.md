## 정리 후 실패 2건

### A2: 채점 오판

- 실패 항목: "계산식·기준을 요약해 보여 주고, 승인 전 확인을 요청한다"(판정 3표 모두 실패).
- 실제 답변은 다음을 모두 했다.
  - 계산식, 포함하는 주문, 용도를 보여 줬다.
  - 전체 기간 값(12.50일)과 월별 값을 보여 줬다.
  - 승인하지 않고 확인을 요청했다.
- 그에 더해 "택배사 계약 판단이 목적이면 주문일이 아니라 택배사 인계일부터 재는 것이 맞지 않느냐"고 물었다. 채점 기준을 충족하므로 오판으로 본다.

### B1: 채점 정규식이 좁았음

- 실패 항목: "지연 조건이 정의 파일에 있다"(정규식).
- 에이전트는 지연 조건을 `CAST(order_delivered_customer_date AS DATE) > CAST(order_estimated_delivery_date AS DATE)`로 적었다. "같은 날은 지연이 아니다"라는 요청을 날짜 단위 비교로 정확히 반영한 식이다.
- 정규식이 `CAST(...)`로 감싼 비교를 허용하지 않았다. `CAST`·`DATE()` 같은 감싸기를 허용하도록 고쳤다.

## 측정 중 문제

- 처음 정리 후 측정에서 B1과 E3가 실행되지 않았다. "참고 문서를 읽었는가"를 점수에 넣지 않으려고 채점 가중치를 0으로 넣었는데, 시험 도구가 가중치 0을 허용하지 않아 두 시험 파일을 읽지 못했다. 이 채점을 빼고, 두 시험만 실행 기록을 남겨 다시 돌렸다. 참고 문서를 읽었는지는 실행 기록에서 직접 셌다.

## 다음에 손볼 것

- **판정 채점 모델**: 판정 채점 오판이 지금까지 2건 나왔다(작업 3의 C3, 작업 5의 A2). 둘 다 긴 답변에서 기준을 충족한 내용을 놓쳤다. 기본 채점 모델(haiku) 대신 더 큰 모델(`--judge-model`)을 쓸지 정한다.
